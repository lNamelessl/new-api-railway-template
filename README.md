# New API — Hardened Railway Template

One-click [new-api](https://github.com/QuantumNous/new-api) (Calcium-Ion, the 48k-star one-api fork) LLM gateway for Railway, with a production topology: **MySQL 8.4 + Redis 7.4 + persistent volumes**, all secrets auto-generated, version pinned, and a weekly auto-bump CI.

**Deploy (one click):** [![Deploy on Railway](https://railway.com/button.svg)](https://railway.app/new?github_url=https://github.com/lNamelessl/new-api-railway-template)

> After the template is published this button points at the Railway marketplace page; the pre-publish link above deploys straight from this repo.

## What you get

| Service | Image (pinned) | Notes |
|---|---|---|
| `new-api` | `calciumion/new-api:v1.0.0-rc.37` (via this repo's Dockerfile) | Gateway + web UI, port 3000, healthcheck `/api/status`, persistent volume at `/data` |
| `MySQL` | `mysql:8.4` | Primary datastore, volume at `/var/lib/mysql`, root password auto-generated |
| `Redis` | `redis:7.4` | Cache + session backing, password auto-generated |

An entrypoint wrapper waits for MySQL and Redis before starting the gateway, so a cold deploy never races its own database.

## First login — create the admin account (no default credentials)

new-api has **no default admin password** on this deployment. On first visit the UI redirects to `/setup` where **you** create the root account.

1. Open your Railway deployment URL right after the first deploy.
2. Complete the setup form: choose an admin username and a strong password.
3. Log in, then go to **Channels** to add your upstream provider (OpenAI, Claude, Gemini, ...) and to **Tokens** to mint API keys for the OpenAI-compatible endpoint:

```bash
curl https://YOUR-APP.up.railway.app/v1/chat/completions \
  -H "Authorization: Bearer sk-YOUR-TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"hello"}]}'
```

Do the `/setup` step **immediately** after deploying — until you do, the first visitor to the URL can claim the admin account (standard new-api behavior for any fresh instance).

## Environment variables (pre-configured by the template)

| Variable | Value | Purpose |
|---|---|---|
| `SQL_DSN` | `${{MySQL.MYSQL_ROOT_PASSWORD}}`-backed DSN (expression) | MySQL connection |
| `REDIS_CONN_STRING` | password-injected `redis://` URL (expression) | Redis connection |
| `SESSION_SECRET` | 64-char auto-generated per deployment | Cookie/session signing |
| `CRYPTO_SECRET` | 64-char auto-generated per deployment | Cache-key HMAC |
| `MYSQL_HOST`, `REDIS_HOST` | private-network hostnames (expressions) | Used by the boot wait loop |

Non-secret defaults (`TZ=UTC`, `SYNC_FREQUENCY=60`, `BATCH_UPDATE_ENABLED=true`, `MEMORY_CACHE_ENABLED=true`, `ERROR_LOG_ENABLED=true`, `STREAMING_TIMEOUT=300`) are baked into `entrypoint-wrapper.sh` as code defaults — override any of them by adding the variable on the service.

Only deploy-form input: the MySQL database name (enter `new-api`).

## Security notes

- Every secret (DB root password, Redis password, session/crypto secrets) is generated by Railway's `${{secret()}}` template function at deploy time — nothing secret is stored in this repo or in the template.
- Upstream's well-known `root/123456` bootstrap account is never created here: the database starts empty and root is created only through the `/setup` wizard by whoever deploys.
- Set `SESSION_COOKIE_SECURE=true` and `SESSION_COOKIE_TRUSTED_URL=https://YOUR-DOMAIN` if you want strict cookie/Origin hardening (off by default so first login always works).
- Pinned image + weekly bump: see below. Deploys are reproducible and reviewable.

## Weekly auto-bump

[.github/workflows/weekly-bump.yml](.github/workflows/weekly-bump.yml) runs Mondays 06:00 UTC: it resolves the newest upstream release, verifies the matching Docker Hub tag exists, re-pins the `Dockerfile`, and pushes. Optional smoke-test job needs repo secrets `RAILWAY_TOKEN` + `TEMPLATE_CODE` (skipped otherwise). You can also run it manually via **Run workflow**.

## Local development

```bash
docker build -t new-api-railway .
docker run --rm -p 3000:3000 calciumion/new-api:v1.0.0-rc.37  # upstream image directly (SQLite)
```

## Troubleshooting

- **Deploy loops restarting** — MySQL still initializing (first boot takes ~1-2 min); the wrapper waits up to 5 min per dependency, and Railway restarts on failure. Check `MySQL` deploy logs if it persists.
- **Login fails after restart** — cookies are signed with `SESSION_SECRET`; it is stable per deployment, so this should not happen. If you rotated it, users just log in again.
- **`No database selected` / SQL errors** — make sure the MySQL service variable `MYSQL_DATABASE` is set (template default: `new-api`).
- **401 on `/v1/...`** — create a token in the UI (**Tokens** page) and use it as the bearer.
- **Channel test fails** — that is your upstream provider key, not the gateway; check the channel's base URL/key/model mapping in **Channels**.
